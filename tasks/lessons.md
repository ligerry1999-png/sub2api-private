- 2026-05-24: 本地没有系统级 `go`，后端验证不要默认临时下载 Go 工具链。除非需要本地复现后端问题，否则优先依赖 GitHub Actions 跑 Go 测试和安全扫描，本地只做代码审查、前端检查和必要的轻量命令。
- 2026-06-01: 2核4G 生产服务器不能承担 Sub2API Docker 源码构建，前端 `pnpm run build` 会把内存和 CPU 打满，导致 SSH/nginx 握手超时。部署必须改为 GitHub Actions 构建镜像，服务器只执行镜像加载和容器重启；部署 workflow 默认只手动触发。
- 2026-06-01: 合并官方 Sub2API 新版本时，必须显式检查私有定制路由是否还在，尤其是 `/v1/image-jobs/*` 异步生图接口。升级验收不能只看 `/health` 和首页 200，还要跑定制路由注册测试与线上探针。
- 2026-06-01: 服务器磁盘紧张时优先清 Docker BuildKit 构建缓存和系统旧日志，不要先碰 Postgres/Redis、账号池、图片日志和当前运行镜像。`docker builder prune -af` 可释放本机历史构建缓存，但正式部署已改为 GitHub Actions 构建，所以服务器不应依赖这些缓存。
- 2026-06-01: 生图文件增长主要来自本地文件存储，不是数据库本身。Sub2API 的 `image_logs` 保存原图/缩略图，`image_jobs` 的 `result.json` 可能保存图片响应体，ChatGPT2API 也会保存一份图片；排查磁盘时必须把这三类分开看。
- 2026-06-01: 服务器存储治理优先用保留天数和轻量 systemd timer 收口，避免为清理文件去服务器本地构建镜像。Sub2API 生图日志属于业务可视日志，异步 image-jobs 和 ChatGPT2API 图片属于短期缓存，保留策略应分开。
- 2026-07-16: 从官方 tag 重建私有分支时，不能只看“主要功能”提交；还要对照上一条真实线上分支与旧 `main` 的完整私有提交清单，特别检查账号空间展示、图片协议兼容和 Nginx 大文件配置。旧部署文件不能机械覆盖新配置。
- 2026-07-16: GitHub Actions 构建并不自动等于安全上线。生产部署还应在加载新镜像前标记旧镜像，并在健康检查、Nginx 校验或私有路由探针失败时自动恢复旧镜像。
- 2026-07-27: 解释数据结构变化前必须同时核对运行模式和前端入口；“数据库新增分组”不等于“管理后台直接可见”。SIMPLE 模式会隐藏分组管理页，但活跃公开分组仍可能出现在 API Key、账号和用量筛选中，因此升级测试必须验证真实可见入口和空分组影响。
- 2026-07-27: 用“是否有历史数据”判断全新安装时，普通 ORM 查询可能自动隐藏软删除记录。安装状态判断必须显式包含软删除历史，否则会把操作员曾经删除过数据的系统误判成空库并重新创建默认数据。
- 2026-07-27: 针对共享数据库的集成测试，单独运行目标用例通过并不能证明完整测试包会通过。测试“全新安装”时必须在当前事务中重建最小数据库状态，防止其他测试遗留的数据改变安装状态判断。
- 2026-07-27: 并发测试不能假定“启动第二个 goroutine”就等于它已经加入 singleflight。若调度器让它在首个请求完成后才运行，业务层的防重复限流就是合法结果；测试应同时覆盖复用进行中结果与完成后限流这两种有效时序。
