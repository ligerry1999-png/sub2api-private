# 私有 image-jobs 持久队列改造

> 开始日期：2026-08-02
>
> 目标：合法异步生图请求先持久化并返回 `202 + job_id`，后台继续复用现有用户/账号 Redis 并发槽位；不再用固定 4 个进程槽位充当接收上限。
>
> 验证边界：440 条批量验收只能使用假上游，禁止向真实生图账号发起 40/50/440 并发请求；生产服务器禁止构建。

## 实现

- [x] 原子保存任务元数据、请求正文和安全请求元数据，不落盘完整 Key
- [x] 增加独立 Redis ready/delayed/active 队列、幂等入队和失败恢复
- [x] 用有界 dispatcher 领取任务，真实执行继续服从用户与账号并发槽位
- [x] 本地容量暂满、内部并发 429、暂时无账号时重新排队，不把任务标成最终失败
- [x] 支持 pending/running 取消、重启恢复和过期 lease 回收
- [x] 结果改为有界/流式落盘，保持 Base64 与 `result_delivery=file_url` 兼容
- [x] 清理逻辑只删除终态任务，不删除 pending/running
- [x] 保持现有 create/get/result/cancel 路由和响应字段兼容

## 配置与部署

- [x] 增加队列条数、字节容量、worker ceiling、重试与 lease 配置
- [x] 把配置传入生产 Docker Compose，废弃无效的 `ASYNC_IMAGE_MAX_CONCURRENT=4` 接收门禁
- [x] 部署时暂停领取新任务，只等待 running，保留 pending 并在重启后恢复
- [ ] 加入队列深度、最老任务、重试、worker 和账号槽位监控
- [x] 记录旧版本回滚时 pending 队列的兼容处理

## 验证

- [x] 单元测试覆盖 202 接收、队列满、取消、重试、幂等和重启恢复
- [x] 假上游模拟 440 条提交全部返回 202，不发生真实生图
- [x] 假账号并发 50 时真实执行峰值不超过 50 且能够达到 50
- [x] 用户并发低于账号并发时执行峰值取较小值，任务继续 pending 而非失败
- [ ] 运行前端/后端相关测试、完整 CI、安全扫描和 build-only
- [ ] 上线前检查数据库、Redis、磁盘、活跃图片任务与回滚点
