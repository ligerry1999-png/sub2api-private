# Codex 生图中转站：小白安装与使用说明

> 最后核验日期：2026-07-22
>
> 适用对象：刚安装 Codex、不会写代码，希望通过 Sub2API 中转站对话生图的人

## 先说结论

把本文“复制给 Codex 的完整指令”整段发给新电脑上的 Codex，它会一步一步帮使用者完成本机设置。

设置完成后，使用者不需要再写接口代码，只要对 Codex 说：

```text
请通过中转站生成一张中国山水画，竖版 2:3，高清，不要文字。完成后直接显示图片，并告诉我实际像素尺寸。
```

这里的“实时生图”是指：在当前对话里说一句需求，Codex 自动提交任务、等待、下载并显示结果。它不代表图片瞬间完成；正常情况下需要等待几十秒到数分钟，最长可等待 10 分钟。

## 可以直接转发给朋友的一段话

```text
我给你开通了一个可以在 Codex 里对话生图的中转站。你不需要懂编程，也不要把访问密钥发给我、发到聊天里或截图给别人。请先打开 https://sub2api.tanzhongyu.asia/keys，为你自己的电脑新建一把独立 Key；建议名称写“你的名字-电脑名称”。然后把下面那段“安装指令”完整复制给你电脑上的 Codex，按它一次一个步骤的提示操作。需要输入 Key 时，只能在它打开的本机隐藏输入框或终端提示里输入，不能粘贴到聊天框。设置完成后，你只要用中文描述想画什么、横版还是竖版、是否高清，Codex 就会自动等待并把图片显示出来。
```

## 朋友第一次需要做什么

1. 打开 Codex，确认能正常发消息。
2. 登录中转站的 Key 页面：<https://sub2api.tanzhongyu.asia/keys>。
3. 新建一把只给这台电脑使用的 Key（访问密钥）：它像这台电脑进入中转站的门卡，用来识别身份、检查权限和记录用量。
4. 不要把 Key 发进 Codex 聊天框。等 Codex 明确打开“本机隐藏输入”步骤时，再在本机输入。
5. 把下一节的完整指令发给 Codex，然后按它的提示一次只做一步。

建议管理员为每个人单独创建账号或 Key，并设置合理额度。不要多人共用同一把 Key；这样某个人不再使用或 Key 泄露时，可以只停用那一把，不会影响其他人。

## 复制给 Codex 的完整指令

请从“开始”到“结束”完整复制，不要在里面填写真实 Key。

```text
【开始】

请帮我在这台电脑上安装“通过 Sub2API 中转站对话生图”的本机能力。我完全不懂技术，请一直用简单中文解释，一次只让我完成一个动作；能由你安全完成的步骤请直接完成，不要让我手敲代码。

已知固定信息：
- Base URL（接口根地址）：https://sub2api.tanzhongyu.asia/v1
- 文字模型：gpt-5.6
- 生图模型：gpt-image-2
- Key 管理页面：https://sub2api.tanzhongyu.asia/keys
- 异步生图提交接口：POST https://sub2api.tanzhongyu.asia/v1/image-jobs/images/generations
- 异步改图提交接口：POST https://sub2api.tanzhongyu.asia/v1/image-jobs/images/edits
- 查询任务接口：GET https://sub2api.tanzhongyu.asia/v1/image-jobs/{job_id}
- 领取结果接口：GET https://sub2api.tanzhongyu.asia/v1/image-jobs/{job_id}/result

必须遵守的安全要求：
1. 绝对不要让我把真实 API Key 粘贴进聊天框、代码、截图或普通日志。
2. 需要 Key 时，请根据这台电脑的系统打开本机隐藏输入方式，并把 Key 存在系统安全凭据区。macOS 优先使用 Keychain（系统钥匙串）；Windows 优先使用 DPAPI / Credential Manager（系统加密凭据）；Linux 优先使用 Secret Service / Keyring（系统密钥环）。如果系统确实没有安全凭据区，才允许使用仅当前用户可读的本地文件，并明确告诉我这是降级方案。
3. 每人、每台电脑使用独立 Key；不要复用管理员或其他人的 Key。
4. 任何输出都不能显示完整 Key。验证时只能报告“已读取/未读取”，最多显示末尾 4 位。
5. 只修改这台电脑的 Codex 用户设置和你新建的本机辅助文件；不要修改远程服务器，不要重启远程服务，不要在远程服务器构建程序。
6. 修改已有文件前先备份，保留所有与本任务无关的原内容。不要覆盖整个文件。
7. 真正提交测试图片会消耗额度，提交前必须先问我是否同意；文字连通测试也要说明会产生少量用量。

请按以下顺序执行：

第一步：检查环境
- 识别当前系统是 macOS、Windows 还是 Linux。
- 检查 Codex 版本，以及用户目录中的 ~/.codex/config.toml 和 ~/.codex/AGENTS.md 是否存在。
- 检查当前版本是否支持 model_providers 的 command 鉴权；如果不支持，请先引导我升级 Codex，不要退回到把 Key 明文写进配置文件。
- 如果文件存在，先做带日期时间的备份；如果不存在，再创建。
- 先告诉我你检查到了什么，再继续。

第二步：安全保存 Key
- 引导我打开 https://sub2api.tanzhongyu.asia/keys，新建一把以“姓名-电脑名称”命名的独立 Key。
- 不要让我把 Key 发给你。请创建一个只在本机运行的隐藏输入步骤，把 Key 保存到当前系统的安全凭据区。
- 在 ~/.codex/bin/ 下创建一个读取凭据的小工具。它只把 Key 交给本机程序使用，不把 Key 写进日志或聊天。
- 给新建文件设置最严格、合理的当前用户权限。
- 验证能否读取非空 Key，但不要打印 Key 本身。

第三步：配置 Codex 文字请求走中转站
- 在用户级 ~/.codex/config.toml 中保留原设置，并安全合并以下配置。不要使用项目目录里的 .codex/config.toml 存放鉴权配置。

  model = "gpt-5.6"
  model_provider = "sub2api"

  [model_providers.sub2api]
  name = "Sub2API 中转站"
  base_url = "https://sub2api.tanzhongyu.asia/v1"
  wire_api = "responses"

  [model_providers.sub2api.auth]
  command = "这里替换成第二步创建的本机凭据读取工具的绝对路径"
  timeout_ms = 5000
  refresh_interval_ms = 0

- 如果现有 config.toml 已包含相同配置，请更新对应字段，不要重复添加表格区块。
- 检查 TOML（配置文件格式）语法是否正确：它是 Codex 读取设置的文本格式，用来告诉 Codex请求发到哪个中转站、使用哪个模型。

第四步：创建本机生图工具
- 在 ~/.codex/bin/ 下创建一个适合当前系统执行的 sub2api-image 工具。
- 工具必须从第二步的本机凭据读取工具取 Key，不能把 Key 硬编码在脚本中。
- 支持这些输入：提示词、图片尺寸、质量、输出目录；默认 model=gpt-image-2、n=1、quality=high。
- 竖版默认 size=1024x1536，横版默认 size=1536x1024，方图默认 size=1024x1024。
- 如果用户指定的比例不是上游原生支持的比例，例如 3:4，不要假装 1024x1536 就是 3:4。先说明最接近的原生尺寸是 1024x1536（2:3），再询问是接受 2:3，还是生成后在本机裁剪成 3:4。
- 默认使用异步接口提交，并设置 result_delivery=file_url。
- 如果用户提供了本机参考图，则改用 /image-jobs/images/edits，以 multipart/form-data 上传图片和提示词；没有参考图时使用 /image-jobs/images/generations。
- 从响应中取得 job_id，每 5 秒查询一次状态，最长等待 10 分钟。
- 状态成功后调用结果接口，兼容 URL 和 Base64 两种返回方式，下载到本机独立输出目录。
- 下载后检查文件确实是图片，读取并报告实际像素尺寸；不要只相信请求中填写的尺寸。
- 若 10 分钟后仍未完成，报告 job_id 并停止，不要自动重复提交，避免重复扣费。
- 对 401、403、429、502 和网络超时给出小白能听懂的说明：
  - 401：Key 无效或没有正确读到。
  - 403：这把 Key 所在分组没有生图权限。
  - 429：额度、并发数或请求速度达到限制。
  - 502：上游生图服务临时失败。
- 工具运行时绝不能输出 Authorization 请求头或完整 Key。

第五步：让以后每次对话都知道怎么生图
- 保留 ~/.codex/AGENTS.md 原内容，在末尾加一个清楚标记的“Sub2API 生图规则”区块，写入这些规则：
  1. 用户说“生图、画图、生成图片、改图”时，优先调用刚创建的本机 sub2api-image 工具。
  2. 信息不够时，只询问画面内容和横竖比例；其余使用默认值。
  3. 默认使用 gpt-image-2、1 张、high；竖版 1024x1536，横版 1536x1024，方图 1024x1024。
     用户要求 3:4 等非原生比例时，要说明差异，并让用户选择“使用最接近尺寸”或“生成后本机裁剪”，不能虚报比例。
  4. 用异步任务等待结果。等待期间简短告诉用户仍在生成，但不要重复提交。
  5. 成功后在 Codex 中直接显示本机图片，并报告保存路径、实际像素尺寸、job_id。
  6. 用户要求 2K 或 4K 时，可以把要求写进提示词并使用服务允许的最大尺寸，但必须说明上游不保证原生 2K/4K，最后以下载文件的实际像素为准；不要虚报 4K。
  7. 不得泄露 Key。
  8. 用一句大白话说明链路：我的描述 → 这台电脑上的 Codex → HTTPS 加密请求到 Sub2API 中转站 → 上游 gpt-image-2 生图 → 中转站返回结果 → Codex 下载并显示。

第六步：重启与验证
- 告诉我需要退出并重新打开 Codex，因为用户配置和全局 AGENTS.md 通常在新会话启动时读取。
- 关闭前先告诉我：重新打开后发送“继续验证刚才的 Sub2API 生图安装”。
- 重启后先检查配置是否生效，但不要打印 Key。
- 先向我申请同意，再做一次最小文字连通测试和一次生图测试。
- 生图测试提示词使用：
  “一只白色陶瓷杯放在浅木桌上，窗边自然光，干净背景，写实摄影，方图，不要文字。”
- 成功后直接显示图片，并告诉我：使用的 Base URL、文字模型、生图模型、保存位置、实际像素、job_id。

最后请给我一份很短的完成报告，包含：
- 已修改或新建了哪些本机文件；
- 备份放在哪里；
- 文字和生图测试是否通过；
- 如果失败，根本原因是什么、我下一步只需要做什么；
- 以后我可以直接说的示例：
  “请通过中转站生成一张夏日海边咖啡店，竖版 3:4，高清，不要文字。完成后直接显示，并告诉我实际像素尺寸。”
  如果 3:4 不是上游原生比例，请先让我选择使用 2:3，还是在本机裁剪成 3:4。

【结束】
```

## 这条链路到底怎么走

```text
你用中文说画面需求
        ↓
你电脑上的 Codex 理解需求并调用本机生图工具
        ↓  HTTPS 加密请求 + 这台电脑自己的 Key
Sub2API 中转站鉴权、记账并转发任务
        ↓
上游 gpt-image-2 生成图片
        ↓
Sub2API 返回任务结果
        ↓
Codex 下载到你的电脑并在对话里显示
```

这不是通过 ChatGPT 网页偷偷点按钮，也不是让 Codex 自己在本地“画”一张图。真正执行生图的是上游图片模型；Codex 负责理解指令、提交任务、等待结果和把文件展示出来。

## 使用者必须知道的四件事

1. **Key 不能发进聊天。** 聊天内容可能进入历史记录或上游请求，Key 一旦泄露，别人可能消耗你的额度。
2. **一人一 Key。** 这是后续维护最重要的习惯，方便单独限额、审计和停用。
3. **“高清”不等于真实 4K。** 提示词可以描述高清细节，但真实像素由上游能力决定，必须检查下载文件的宽和高。
4. **超时不要连续点。** 任务可能还在上游排队；应保留 job_id 继续查询，盲目重试可能生成多张并重复扣费。

## 常见问题

- Codex 一开始完全不能聊天：先完成 Codex 自身的首次登录；没有可运行的 Codex 会话，就无法执行上面的自动安装指令。
- 打不开 Key 页面或没有创建权限：联系管理员给这个人创建独立账号或独立 Key，不要临时共用管理员 Key。
- 文字能用、生图报 403：通常不是电脑坏了，而是该 Key 所属分组没有开生图权限，请管理员调整分组。
- 报 401：重新检查这台电脑是否保存了正确 Key，不要把 Key 发给别人检查。
- 报 429：检查额度和并发限制，等待后再试，不要连续重复提交。
- 等待超过 10 分钟：把 job_id 留给管理员排查，先不要创建相同任务。
- 想换电脑：在新电脑上重新创建独立 Key 并重走一次安装，不要复制旧电脑的系统凭据。
